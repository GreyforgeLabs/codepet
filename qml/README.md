# CodePet QML UI

Rust is the authority for care, sleep, rewards and growth. QML renders snapshots;
animations and cosmetic timers grant no stats or XP. The v0.4 desktop pet opens a
compact work card. Readiness and a bounded one-shot deadline can request a read-only
scout; Fix and reviewed Apply remain explicit. The bar popup owns care and observer
connections, and a native work window provides advanced tasks and full review.

See [overlay capabilities and live validation](../docs/desktop-overlay.md) and
[Quickshell host controls](omarchy/README.md) for the primary desktop entry.

## Components

Current work surfaces:

- `shared/WorkCard.qml`: portable compact status/finding card, with level, XP and age.
- `shared/PetAge.js`: age from the durable current-life timestamp, never session time.
- `omarchy/WorkController.qml`, `WorkRpc.qml`, `WorkModel.js`: shared work state,
  bounded argv transport, one-shot scouting and explicit job/review actions.
- `omarchy/WorkPanel.qml` and `work.qml`: native advanced form and before/after review;
  the same entry supports the compact fallback. Closing it does not kill a supervisor.

Companion rendering and retained preview components:

- `shared/Panel.qml`: the v0.2 window views `home`, `care`, `companion` and `life`, kept for
  the standalone preview; adoption when no companion lives, a "Set up life rules" banner
  for an unarmed life
- `shared/DesktopPet.qml`: the desktop pet. It draws a parsed `bar-state.json` and
  sends nothing: `shared/petstate.js` picks the face in the one shared order, and
  `shared/OverlayFace.js` turns it into an animation and a picture-only thought bubble
  (app tiles, the need's care icon, bandage, star, heart). Celebrations play once. A click
  hops (Calm mode: bubble only), shows a heart and toggles the compact card. A new process
  never replays a celebration that was in its first export. One bounded
  cosmetic scheduler plus one single-shot wake timer for the face's `wake_at_ms`; drag/pin placement and the compact card are coordinated by the host; aquatic
  companions stay in their habitat
- `shared/petstate.js` (and the identical `omarchy-plugin/petstate.js`): the shared
  priority, GENERATED from `docs/v0.3/contracts/agent_vectors.json` by
  `tools/petstate/gen_petstate.py`; never edit it by hand
- `shared/PetSprite.qml`: passive raster renderer. It sets one frame URL from the species
  manifest's explicit frame lists (`qml/assets/pets/<id>/s<stage>/b|cNN.webp`), mirrors
  floor species when walking left, and shows `_placeholder.webp` for a missing or broken
  file (and `_memorial.webp` for the memorial). No timers or backend calls
- `shared/PetRegistry.js` (generated by `tools/petart/extract.py --index`) and
  `shared/PetCatalog.js`: species, stages, frame lists, geometry and care labels
- `shared/PetStateMachine.js`: pure mapping from snapshot facts to the 15 animation states
- `shared/PetChooser.qml`: look switching (cosmetic `pet.select`) and species choice for
  adoption
- `shared/LifePanel.qml`, `shared/RulesCard.qml`, `shared/AdoptionPanel.qml`,
  `shared/MemorialPanel.qml`: life status, rules acknowledgement and mode, leniency,
  Pause/Travel, retirement by typed name, adoption and the memorial
- `shared/LifeText.js`: all life copy and attended-time math (`.pragma library`, no
  imports; the installer copies it byte for byte into the bar plugin)

Retained from v0.1:

- `shared/PetCare.qml`: explicit care controller of the preview's Care view, including the
  atomic care routine
- `standalone/Main.qml`, `standalone/PreviewHost.qml`, `standalone/Fixtures.js`:
  pure-QML fixed-fixture preview of the v0.2 views
- `shell.qml`: Quickshell host entry of the desktop pet (at `qml/` so `shared/`, `omarchy/`
  and `assets/` are inside its config folder): one transparent, non-focusable,
  click-through layer-shell overlay whose input region covers the pet and open card.
  A click opens that card; Care opens the bar popup at Home. The process exits on Off and when "Pet on my
  desktop" is off, and follows Calm mode live ([omarchy/README.md](omarchy/README.md))
- `standalone/OverlayPreview.qml`: fixture-only desktop-pet preview in a normal window
- `omarchy/HostAdapter.qml`: explicit `codepet rpc` transport (one process per request);
  `omarchy/BarStateWatcher.qml` and `omarchy/BarState.js` read `bar-state.json` (v1 and v2)
  without RPC; `omarchy/OverlayFlow.js` holds the exit, settings and Home rules
- `tests/`: headless UI/transport harnesses, not product runtime code

Quickshell imports remain confined to the host entries, the Omarchy adapter
and its test harnesses.
A non-Quickshell standalone product host remains a portability goal. The optional
Python test runner is a test dependency, not a replacement product architecture.

## Host contract

Shared components receive a `host` object. Required:

- `snapshot`: last successful `state.get` result; only the host replaces it
- `busy`: an outstanding request; hosts refuse overlap with `CLIENT_BUSY`
- `lastError`: `CODE: message`, cleared on the next non-state request
- `request(method, params, callback[, requestId])`: a v1 response envelope to the
  callback; optional request IDs support identical acceptance, care, adoption, look and
  life retries

Optional (each is feature-tested, so an older host keeps working):

- `clientTag`: request-id prefix for retry keys (`overlay`, `preview`; default `ui`)
- `presentationLocks`: integer the care routine increments while its cosmetic
  choreography runs, so the scene holds still
- `openCompanion()`, `openLife()`: ask the host to open that tab; they only signal

`Panel`, `LifePanel` and `PetChooser` take an optional `registry` (the generated
`PetRegistry.REGISTRY`); without it `LifeText` uses its built-in roster, which
`test_life_text.mjs` keeps identical to `registry.json`.

The v0.2 snapshot adds `life` (null when no companion lives), `lifecycle` (including the
`critical` card), `unseen_events` and `memorial`. The life methods are `lifecycle.rules`,
`pet.rules`, `pet.adopt`, `pet.select`, `pet.configure_life`, `pet.retire`,
`pet.memorial` and `pet.events_seen`; `pet.pause` is Pause/Travel. Shapes and rules:
[docs/lifecycle.md](../docs/lifecycle.md). Hosts must not issue RPC in response to a
snapshot change or a file event; the Quickshell host merges `bar-state.json` as data only.

`snapshot.care` provides bathroom/rest counters and sleep status (its v0.3.0
`ready_to_work`/`readiness_reasons` keys are inert compatibility values). Care mutations
are `pet.care {action: food|water|play|wash|bathroom|routine}`, `pet.sleep {}` and
`pet.wake {}`. The UI care routine is one click and one request, the atomic backend
`pet.care {action: "routine"}`: storage fills every needed bar in one transaction; no timer
ever sends a request. Each confirmed care/sleep action is followed by an explicit state
refresh. The task methods (`task.*`, preflight, acceptance) are retired in v0.3.0 and are
not sent by any QML.

## Care, motion and sleep

- Four high-is-good bars: Nourishment, Hydration, Mood and Hygiene
- Food/water/play/wash fill their bar to 100; no care action grants XP
- Bathroom due makes the wash button say `Bathroom + wash`; the tree always offers
  the actual bathroom action. A plain wash cannot clear bathroom due in Rust
- Bed discloses a two-minute nap. Early wake preserves remaining rest; review and
  acceptance remain available while sleeping
- Countdown uses local display-only elapsed time at 1 Hz while visible/asleep.
  At zero it explicitly asks for Refresh/Wake to confirm saved readiness. It never
  issues RPC, persists ticks, wakes the pet, or enables Start
- Pose changes are capped at 5 FPS (200 ms), including short reactions. Hidden or
  minimized windows, reduced-motion and quiet mode stop pose ticks. Sleeping uses
  a static pose. No interpolated animation runs at an unbounded render-loop rate
- Text feedback is retained with reduced motion, plus a four-entry care trail in
  this view. The durable task timeline is separate. Sound is off
- UI options are session-local; this milestone does not persist reduced-motion or
  quiet-mode preferences or integrate compositor lock signals

The timeline uses `events.subscribe {after_seq, limit:50}` only on a user click.
The first load shows the latest 50 saved events (ending at the snapshot's
`last_seq`), so current work is visible without paging through old history;
"Load older" pages earlier events on an explicit click and "Load more" fetches
newer ones. It displays actual saved `task.state` transitions, validates event
shapes, bounds its list to 100 entries and marks omitted/malformed content. It does **not** invent
file reads, edits, tests, commands or completion percentages. Refresh is explicit;
there is no process polling and no live provider-operation stream in this milestone.

Acceptance displays the stored receipt, including isolated demo XP, real-work XP
and any historical care reward from older receipts. Small eligible mock artifacts
may grant 20 demo XP; failed checks grant none. No mock result earns real-work XP.
Levels never expand providers, scope or permissions. Higher-tier template execution
and richer unlocks remain deferred behind real-provider and containment gates.

## Fixed-fixture standalone preview

With a Qt6 runner: `qml6 qml/standalone/Main.qml`.

The banner says `PREVIEW – not connected to Rust; no rewards are stored`. Fixtures:
`idle`, `ready`, `bathroom_due`, `sleep_due`, `sleeping`, `demo_level_2`, `running`,
`review_not_verified`, `review_check_failed`, `recovery_required`, and the v0.2 life
fixtures `unarmed`, `warning_thirst`, `critical_hunger`, `gentle_fainted`,
`death_pending_review`, `no_life_memorial`, `evolved_unseen`, `paused`,
`aquatic_goldfish` and `robot_working`.

Preview snapshots never mutate in response to care, sleep, Start, acceptance,
discard, cancel or recovery: those requests return `PREVIEW_ONLY`. Draft/preflight
responses are canned for form inspection; the token is invalid outside preview.
The fixed event history is explicitly fixture data, not work that ran. Select
`ready` to inspect fresh-preflight/acknowledgement Start gating. Selecting a fixture
is not a real state mutation.

## Validation

Current gates: the QML job in [`.github/workflows/qml.yml`](../.github/workflows/qml.yml)
(every `tests/*Smoke.qml`, the Python and node suites, `copy_lint.py` and `qmllint`), with
results recorded in [docs/validation.md](../docs/validation.md). The section below is the
historical record of the care/progression revision (v0.2). Its task-era results (draft,
review, preflight, readiness and timeline checks) describe QML that v0.3 retired
(SPEC-v0.3 §6.5); those smokes no longer exist, and the commands below list only smokes
that still do.

### Validation in a headless build environment without Quickshell (2026-10-15, care/progression revision)

Tested with **Qt 6.8.3 / PySide6 6.8.3**, offscreen Linux only. PySide6 was installed
from PyPI into `/tmp/codepet-qt`; it is not a project/runtime dependency. No packages
or launchers were installed on the user's computer. Exact commands:

```sh
python -m pip install --target /tmp/codepet-qt PySide6==6.8.3
mkdir -p /tmp/codepet-qt-cache
export PYTHONPATH=/tmp/codepet-qt
export XDG_CACHE_HOME=/tmp/codepet-qt-cache
export QT_QPA_PLATFORM=offscreen
python qml/tests/run_qml.py qml/tests/PreviewSmoke.qml
python qml/tests/run_qml.py qml/tests/CareSmoke.qml
python qml/tests/run_qml.py qml/tests/CareFlowSmoke.qml
/tmp/codepet-qt/bin/pyside6-qmllint \
  -I /tmp/codepet-qt/PySide6/Qt/qml -I qml \
  qml/shared/*.qml qml/standalone/*.qml qml/tests/*Smoke.qml
```

Results:

- `PreviewSmoke.qml`: 34 checks, 0 failures; retained draft, review, failed-check,
  override-byte-limit and recovery gates
- `CareSmoke.qml`: 26 checks, 0 failures; actionable care/readiness, sleeping/bathroom
  gates, stale-care preflight invalidation, no RPC from countdown, hidden/reduced/
  quiet animation pause, actual timeline events and isolated demo progression
- `CareFlowSmoke.qml`: the routine is one atomic request with a cosmetic choreography
  (no request from its timer), Stop/hide end the choreography, a busy host refuses it,
  no stranded routine and no task launch; pending/failure/retry-key choreography
- Qt6 `qmllint`: no output on shared/standalone components and these smoke tests
- Standalone offscreen rendering inspected at 720 × 900; this is not a live desktop
  or accessibility certification

Quickshell was not installed in that build environment. Its existing transport
was left unchanged. `tests/quickshell/real_rpc.qml` was updated for mandatory care,
care debits and demo-only receipts but was **not rerun here**. Prior 2026-10-14
headless Quickshell 0.3.1 validation on a local workstation is historical evidence only, not
certification of this care revision. The adapter still uses argv arrays (no shell),
64 KiB frame checks, one-shot response timeout and per-job supervisor lifetime.
Its known newline-free stdout buffering and shell-reload lifetime limits remain.

Not validated: live Omarchy/Quickshell, visible Wayland/X11 desktop, real keyboard
and screen-reader workflows, compositor lock signals, packaging, resource budgets
or performance claims. No real provider or host-project writing is enabled.

## Target-host manual checklist

1. Verify every preview fixture and prominent preview/simulation labels
2. With a real mock RPC host, care to 100 and observe persisted state after reopening
3. Start only after fresh exact-revision preflight and acknowledgement; changing care
   or draft must demand re-preflight, never auto-start
4. Bathroom due requires tree/bathroom action; ordinary wash leaves the badge due
5. Bed/wake and reopen preserve rest credit, show due state, and never start work
6. Review/accept while sleeping works; acceptance leaves care alone and grants at most
   one eligible demo reward. Failed checks remain failed and grant no XP
7. Hide/minimize/reduce motion, then inspect timers and CPU; measure rather than infer
8. Check keyboard focus, screen-reader labels, small-window scrolling and theme contrast
