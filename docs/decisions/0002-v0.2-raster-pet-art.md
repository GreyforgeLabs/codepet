# ADR 0002: CodePet v0.2 ships raster companion art, not SVG generators

- **Status:** accepted for the private v0.2.0 testing prerelease, as a recorded departure
  from issue #5's asset contract. Carried unchanged into the first public release, v0.2.1
  (2026-10-15).
- **Date:** 2026-10-15
- **Scope:** issue #5 (15 companions with evolution): the shipped art format, the editable
  sources and how the frames are reproduced. The roster, coverage and limits are in
  [pets.md](../pets.md); licensing is in [licenses.md](../licenses.md).

## Context

Issue #5 asks for "one coherent original soft-outlined, limited-palette SVG style" with
"editable SVG/source generators plus exported assets". The first v0.2 build plan followed
it: a shared Python SVG toolkit (`tools/petgen/`) with one `draw()` module per species,
about 2,000 generated SVG files, and SVG safety and geometry tests.

During the v0.2 build the build specification's Amendment A2 (2026-10-15; the v0.2 build
specification is not published) cancelled the SVG toolkit, the SVG rules,
`tools/petgen/` and the species `draw()` modules, and replaced them with raster frames
extracted from GPT Image 2 sheets. The amendment records the switch and its route; it does
not give a longer rationale, so none is invented here.

## Decision

1. **Shipped form.** Each companion is a pack of 192×192 lossy WebP frames with alpha
   (`qml/assets/pets/<id>/s<stage>/bNN|cNN.webp`, thumbnails and a `manifest.json`),
   extracted deterministically by `tools/petart/extract.py` from 4×3 chroma-key sheets
   (two sheets per stage, six per species).
2. **Generation route.** The sheets were generated with GPT Image 2 (OpenAI image
   generation) via the Codex CLI image tool on the project owner's ChatGPT plan, each
   anchored on the species' PR #7 sheet in `docs/art-library/`. Prompts,
   references and hashes are in each species' `provenance.json` beside the sheets.
3. **Editable sources.** The editable sources are those sheets plus the extraction code
   and `tools/petart/overrides.json`, not vector generators. The sheets (about 200 MB) are
   **not in Git**. Every sheet's SHA-256 is recorded in the manifests and in
   [`qml/assets/pets/PROVENANCE.md`](../../qml/assets/pets/PROVENANCE.md).
4. **Reproduction.** `extract.py --check` rebuilds every frame from the sheets and
   byte-compares it with the committed files. The sheets are the release asset
   [`codepet-art-sources-v0.2.tar`](https://github.com/GreyforgeLabs/codepet/releases/download/v0.2.1/codepet-art-sources-v0.2.tar) attached to
   [v0.2.1](https://github.com/GreyforgeLabs/codepet/releases/tag/v0.2.1) (checksum in its `SHA256SUMS`); anyone who extracts it into `art-src/`
   can run the check ([pets.md](../pets.md), "Reproducing the frames").
5. **Tests.** `qml/tests/test_pet_assets.py` (manifest schema, files and hashes, WebP with
   alpha, canvas, margins, ground contact, locomotion, water blocks, anchors) and
   `test_pet_distinctness.py` replace the planned SVG safety and geometry tests. The
   legacy v0.1 ginger SVGs and `test_sprite_assets.py` remain unchanged.

## Consequences

- Issue #5's "SVG style" and "editable SVG/source generators" items are **not met** in
  v0.2.0. Its roster, three stages, 15 states, per-species poses, care labels, aquatic
  habitats and evolution are delivered with raster art.
- Style edits mean regenerating sheets and re-extracting, not editing vector paths.
  Per-cell fixes go through `overrides.json` with a recorded reason.
- The art is AI-generated; its copyright and distribution suitability have not been
  legally reviewed ([licenses.md](../licenses.md)).
- The committed frames are validated in CI without the source sheets; `extract.py --check`
  needs the roughly 200 MB release asset, so it runs locally, not in CI.
- Every companion uses one shared state timing table; per-species timing is deferred
  ([pets.md](../pets.md), Limits).
